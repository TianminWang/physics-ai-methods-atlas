# v0.6 统一方法图谱：交互设计验证

## 核心变化

本版不再把知识库拆成三个互不相连的谱系选项卡。**所有方法拥有唯一的权威记录，并且处于同一张全局方法图中。**

研究主轴与方法图是两个语义上不同的对象。主轴表示完成患者特异物理问题需要什么研究能力；方法图保留技术分类、演变和融合关系。主轴环节通过 `uses_method` 关系连接方法家族或具体方法，并记录实际承担的功能。

## 选择某个研究环节会发生什么？

- **直接方法关联：** 数据中记录了环节 → 具体方法的用途。若被标注“已有文献支持/应用已验证”，必须附有相应论文。
- **家族级关联：** 环节 → 方法家族；方法属于此家族。表示合理的研究应用线索，不能直接推断每个子方法已单独验证。
- **上层家族关联：** 经更广泛的家族分类继承而来的关系，应弱于直接关系。
- **其他方法：** 淡化但仍保留。没有记录映射不等于该方法不可用。
- **方法演化边：** 只有关系本身的 stage_ids 记录其针对的研究环节。边的配色基于 primary_stage_id，不由节点所在分区推断。

一个研究环节的相关方法集合可能存在多个不连通的子图。不能为了连通而编造继承关系。

## 六个视觉区域不是唯一父类

数值与物理、优化反演、概率同化、神经求解、生成式、动力学与控制，是**仅用于定位的非排他视觉分区**。每种方法显示一次，但允许保留多个 method → family 关系，详情栏可查看完整家族标签。

底层完整知识图不是单个 DAG：方法“扩展/融合”子图与家族分类子图分别有无环约束；对照、应用、功能和模型更新属于其他有类型关系。

## 如何体验？

1. 选择研究主轴环节，在功能映射区直接查看“环节 → 方法家族/方法”的功能文字。
2. 点击映射卡片，对应方法节点在全局图内进一步突出。
3. 点击方法查看核心机制、应用角色、所属多个家族、Landmark 与可选优先阅读资料。
4. 点击方法之间的演化边，查看具体技术变化、目标瓶颈、代价和支持论文。
5. 默认每个区域显示少量方法，可单独展开或一键展开全部；并提供搜索、缩放、拖动、分类边/对照边开关与中英文切换。
6. 手机端默认保留文字可读性，不会把整图强行缩成一屏。

## 下载与运行

在仓库 **GitHub Actions → Validate atlas data → 最近的成功运行 → Artifacts** 下载 `atlas-unified-v06`，解压后双击 `index.html`，无需启动服务器。

开发者从仓库根目录运行：

```bash
python -m pip install -r requirements-dev.txt
python -m scripts.build_v06 --site build/viewer-v06
```

桌面和手机浏览器截图在 **Unified method graph browser review** 工作流的 Artifacts 中。

## v0.6 验收边界

这是从真实全量方法记录生成的**统一大图原型**，并非最终正式在线网站。方法数量随仓库变化，超大规模图仍需后续探索性能与布局优化。进入 v1.0 前优先评估：

- 主轴→家族的映射是否可见、可理解；
- 直接证据与家族推及是否容易区分；
- 六个视觉区域是否合理且不会造成强制归属错觉；
- 演进边的机制、瓶颈和证据是否容易打开；
- 是否需要进一步增加小地图、路径追踪及局部连通分量浏览。

Start Here 是减小阅读量的可选建议，并不存在强制1–2篇的数量规则。
