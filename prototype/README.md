# v0.5 交互式布局原型 · 使用与验收说明

## 这是什么？

这是从 [Physics AI Methods Atlas](../README.md) **现有权威 JSON 数据**构建的小规模交互原型。它专门用三个真实方法家族验证我们已确定的“研究主轴 → 功能关系 → 方法谱系 DAG”是否能作为最终网页的统一布局。

- **传统与概率反问题：** 最小二乘、Gauss–Newton、LM、正则化、贝叶斯与代理反演。
- **神经算子与物理约束：** 神经算子、DeepONet、FNO、PI-DeepONet、PINO、Geo-FNO、PINN 等。
- **生成式建模与反问题：** 变分推断/VAE、Normalizing Flow/Flow Matching、DDPM/Score-SDE/DPS、物理信息扩散。

**方法节点与文献并没有被复制为第二套可维护数据。** `scripts/build_prototype.py` 每次从仓库原有数据提取这一小部分。界面的短标签仅是可读性摘要；学术证据仍来自原始关系记录。

## 如何实际打开页面？

### 推荐：直接下载 GitHub Actions 的离线 HTML

进入本仓库的 **Actions → Validate atlas data → 最新成功运行 → Artifacts**，下载 `atlas-interactive-layout-v05` 压缩包。

解压后，**双击 `index.html` 即可直接打开**。其中已嵌入当次构建的真实数据，并保留 `app.js` 与 `style.css`，不需要联网、安装 Python 或运行本地服务器。

同一次更新的 **Actions → Prototype UI smoke and screenshots** 下提供 `atlas-v05-layout-screenshots`，包括桌面中英文与移动端中文截图。

### 开发者本地预览

从仓库根目录运行：

```bash
python -m pip install -r requirements-dev.txt
python -m scripts.build_prototype --site build/prototype
```

然后直接打开 `build/prototype/index.html`。如果修改了核心 JSON，请重新执行构建以避免使用旧导出。

在仓库源目录下的 `prototype/index.html` 是**前端模板**；在没有生成 `prototype/data/preview.json` 的情况下，不应直接双击它。

## 交互与语义说明

- 点击主轴环节：高亮与该研究目标相关的方法关系；不意味着该方法只属于这一个环节。
- 切换三条谱系：展示不同方法家族和相应演化结构。
- **默认核心节点**：减少图的拥挤；勾选“展开全部节点”即可查看当前谱系完整示例。
- 点击具体方法：右侧查看核心思想、局限、Start Here（非强制阅读）及 Landmark 论文。
- 点击方法演进关系：右侧查看**技术变化、所针对的瓶颈、支撑论文、关联研究环节及代价**。
- 方法扩展使用实线，融合使用另一种线型，分类只用中性色；研究环节用固定颜色。**颜色不代表算法优劣或论文影响力。**
- 支持中英文切换、搜索、家族高亮、分类边显示、缩放与画布拖动；在手机上为了保留文字可读性，默认不强行缩放到“全部节点一屏可见”。

## 验收标准（v0.5）

- [x] 从权威数据自动生成原型，保留唯一方法 ID。
- [x] 三条谱系、六环节和原始关系均可重建。
- [x] 论文入口、技术瓶颈、演进类型和关联配色正确。
- [x] 中英文浏览、搜索、缩放和拖拽具备基础交互。
- [x] 使用 Playwright/Chromium 测试桌面和手机操作，导出截图。
- [ ] **人工视觉评估：** 检查密集交叉边、标签挡住节点、颜色与线型可读性。
- [ ] **正式推广判定：** 确认对普通研究读者足够清楚后，才将同一布局机制推广到全量图谱。

## 目前不是 v1.0 的功能

这仍然只是**三个真实方法分支的布局验证**。尚未提供61+节点的全量展开、全局搜索和所有论文/专著的统一浏览，也未自动上线正式 GitHub Pages。

正式版应在此基础上添加**分层展开、按需加载、全局搜索、跨家族关系聚焦、移动端导航与稳定部署**。如果原型通过视觉审查，则不需要重新设计其语义和核心交互，只需扩展数据范围、布局策略和浏览层次。
