# 统一主轴—方法 DAG 知识图谱：v0.3 架构说明

## 0. 核心目标

知识图谱统一回答三个问题：

1. **主轴：** 一个有限观测下的物理反问题如何连接正向模拟、参数/状态推断、可信预测、反事实干预和持续更新？
2. **方法：** 哪些独立的方法家族与具体方法可以支持每个研究环节？它们不必且不应被某个环节独占。
3. **创新：** 方法 B 相对于前驱 A 究竟改变了什么、针对什么技术瓶颈、有什么代价；支撑这些判断的论文在哪里？

不建立相互重复的“主轴知识库”和“方法知识库”。**唯一权威数据，多个交互展开深度。**

## 1. 研究主轴：六个能力环节

| ID | 环节 | 配色 | 输入、输出与边界 |
|---|---|---|---|
| `stage.physics-forward` | 物理表征与正向模拟 | 蓝 `#2563EB` | 建立物理方程、参数、边界条件及正向解算子 |
| `stage.observation` | 观测与数据建模 | 青 `#0891B2` | 将状态映射到影像/测量值，表达采样和噪声 |
| `stage.inverse-calibration` | 个体化反演与状态估计 | 紫 `#7C3AED` | 由正向模型与观测估计未知参数/隐藏状态 |
| `stage.prediction-uq` | 可信预测与不确定性传播 | 琥珀 `#B45309` | 在新条件下预测，并评估偏差与不确定性 |
| `stage.intervention-planning` | 反事实干预与决策规划 | 玫红 `#BE185D` | 比较干预候选与优化决策 |
| `stage.continual-update` | 持续观测、同化与模型更新 | 绿 `#15803D` | 后续新观测反馈更新状态、参数与模型 |

正向模型与观测模型**汇合到反演**，并不是 B 必须等 A 完成。持续更新可以反馈到反演、建模和预测。主轴有循环，但**方法演进 DAG 不允许形成历史继承环**。

### 贯穿所有环节的横向可靠性问题

保留独立的 `concern.*` 实体与 `concern_applies_to` 关系：

- 物理一致性与守恒
- 可辨识性与观测信息量
- 离散误差及物理模型失配
- 后验/预测不确定性校准
- 分布外泛化与外部验证

它们不是时间步骤，也不自动是某种单独的算法。

## 2. 方法家族：与主轴解耦的分类森林

方法家族是**概念分类对象**，如数值离散、物理边界模型、反问题优化、概率推断、数据同化、物理约束神经求解、神经算子、生成式模型、系统辨识、控制与规划等。

- `family.*` 可通过 `subfamily_of` 组成家族分类 DAG；
- `method.* → family.*` 由 `member_of_family` 表示，可多重归属，但方法实体永远只存储一次；
- `stage.* → family.*` 或 `stage.* → method.*` 由 `uses_method` 表示**方法在研究环节中的作用**，必须给出中英文 `role`，且不得由此推断历史继承；
- 家族状态 `coverage_status=planned` 是**知识库尚未整理**，不是学科本身尚不存在。

例如：

- `stage.physics-forward → family.operator-learning`：学习可复用的参数→解场映射；
- `stage.inverse-calibration → family.operator-learning`：在反演中用作正向算子代理；
- `stage.prediction-uq → family.operator-learning`：快速预测新参数场下的状态。

**三个功能边都指向同一个家族，没有复制节点，也没有规定这个家族只属于某一环节。**

## 3. 方法演化：分类、创新、融合分开记录

不要把树上的所有边都解释为“后来者改进前驱”。

| 关系 | 方向 | 语义 | 是否表达技术创新 |
|---|---|---|---|
| `specializes` | 子方法 → 一般方法 | 分类/特殊化 | 不必然 |
| `extends` | 新方法 → 前驱 | 有证据支持的技术扩展 | 是 |
| `combines` | 融合方法 → 组件方法 | 将多个机制结合 | 是 |
| `depends_on` | 方法 → 学习前置方法 | 学习依赖关系 | 否 |
| `contrasts_with` | 方法 ↔ 对照方法 | 性能/假设与代价对比 | 否 |
| `introduces` 等 | 论文 → 方法 | 论文对于特定方法的贡献 | 可支持判断 |

对 `extends` / `combines` 强制记录：

- `innovation_detail` / `innovation_detail_zh`：**改变了什么**；
- `bottleneck` / `bottleneck_zh`：**要解决什么技术问题**；
- `evidence_paper_ids`：**有哪篇论文直接支撑**；
- `stage_ids`：在哪些主轴能力环节上有明确联系（可多项）；
- `primary_stage_id`：存在主要问题指向时使用；不允许随意用颜色替代学术论证；
- `tradeoff` / `tradeoff_zh`：成本与局限（可选）。

演进关系本身以`method.new → method.old`存储（子方法指向前驱），显示器可以按阅读习惯反向排版为“前驱 → 后继”。**真实存储方向与视觉排版方向必须明确区分。**

### 例子：FNO → Geo-FNO

- **创新：** 通过学习坐标变形，允许在不规则物理域上使用频谱算子层。
- **瓶颈：** 标准 FNO 的规则网格/几何表示局限。
- **主要研究环节：** 正向建模，蓝色；次要关联可信预测。
- **证据：** Li 等关于 Geo-FNO 的原始研究，附于对应关系记录。
- **注意：** 这不是证明复杂冠脉几何的分布外泛化能力已被充分验证。

## 4. 配色及可视化语义

配色**只表达方法演进边所关联的研究能力**，不能替代关系类型或证据。

| 连线 | 线型（推荐） | 颜色依据 |
|---|---|---|
| 主轴 `feeds_into` | 实线箭头 | 来源环节 |
| 更新反馈 `feeds_back_to` | 虚线箭头 | 更新来源环节 |
| 环节调用方法 `uses_method` | 虚线箭头 | 环节的固定颜色 |
| 方法演进 `extends` | 实线 | `primary_stage_id` 对应颜色；否则中性色 |
| 技术融合 `combines` | 双线/显式融合标记 | 同上 |
| `member_of_family` / `subfamily_of` | 中性细线 | 不着环节色，防止误解为方法创新 |
| `concern_applies_to` | 中性点线 | 不属于流程阶段 |

所有其他受影响环节以标签列出。一条边**不能因为方法能间接用于 PCI，就被错误标成“干预创新”**。这类功能关系另由 `uses_method` 表示。相同颜色仍配合文字、箭头和线型，以便色觉差异用户理解。

## 5. 版本与数据结构

v0.3 扩展了 v0.2 的数据库，不删除已有方法和文献：

```text
data/stages/*.json      主轴、次序、颜色、输入/输出
data/families/*.json    方法家族、建设状态、定义边界
data/concerns/*.json    跨环节可靠性问题
data/methods/*.json     原有方法 + 后续方法
data/relations/*.json   全部有类型关系、证据及演进注释
data/papers/*.json      一份论文、一份权威书目信息
data/books/*.json       专著及章节覆盖
data/problems/*.json    研究问题（不等于方法）
locales/zh-CN.json      历史方法名称的中文显示翻译
```

新建记录采用 `schema_version=2.1.0`；旧的 `2.0.0` 记录仍兼容。**没有进行会破坏原始论文/书籍 ID 的大迁移。**

`python -m scripts.export_unified` 可输出中文或英文同一图谱的显示投影：

- `workflow_axis`：有序环节 ID；
- `nodes`：主轴、家族、具体方法、横向关注点（每 ID 唯一）；
- `edges`：说明、关系类型、线型、主要配色、关联环节及原始证据；
- `views.overview`：用于首页的主轴+家族摘要；
- `views.expanded`：研究图谱的逐层展开基础。

**文献节点不塞满首页**：论文、专著存在权威全量图谱中，未来点击具体方法或关系时再加载。

## 6. 此阶段的明确非目标

- 不新增未经逐篇核验的生成式物理 AI、数值离散、MPC 或强化学习方法节点。
- 不宣称已经完成全部方法谱系或临床有效性审查。
- 不开发完整的交互式 GitHub Pages；简单 Mermaid 是架构示意。
- 不将 1–2 篇优先阅读变成强制规则，也不将全局 Landmark 标签替代具体贡献关系。

**接下来：v0.4 系统补完方法与 Landmark → v0.5 做结构可视化测试 → v1.0 上线正式交互网站。**
