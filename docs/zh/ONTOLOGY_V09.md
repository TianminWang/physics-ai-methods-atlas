# v0.9 统一方法学知识图谱：本体设计提案

> **2026-11-26 说明：** 本文件是以旧样本产生的结构设计提案，供后续审查；现已明确采用[高质量来源先行政策](SOURCE_ADMISSION_POLICY.md)和[归纳式重建路线](EVIDENCE_FIRST_REBUILD.md)，不得将本提案的11种类型、19项 Capability 或旧节点视为必须保留的正式本体。

> 本文是 **Ontology Design Proposal**，并非已正式执行的数据库迁移。方案遵循“一套权威学术数据、多个可切换的知识视角”。

> 与审计报告配套阅读：[《现有结构审计》](AUDIT_V09.md) · [方法类型提案](../../audits/v09/method-kind-proposals.json) · [研究能力层提案](../../audits/v09/capability-layer-proposal.json)。

## 1. 重新界定我们想表示的知识

Atlas 需要同时回答三类问题：

1. **问题视角：** 一个研究问题必须具备哪些能力？各种方法怎样服务这些能力？
2. **体系视角：** 某个技术范式/方法家族下有哪些理论、模型结构、算法及实现？
3. **演进视角：** 某个方法如何改进、借用、扩展或融合前驱？有什么原始学术证据？

三类问题使用**同一个实体和边数据库**，而非三套互不相干的系统。

保留已确认的顶层主轴：

- **Ⅰ 物理系统建模与正向问题**
- **Ⅱ 反问题求解与未知信息推断**
- **Ⅲ 个体化预测、干预与闭环更新**

原六个 `stage.*` 可继续作为子能力及历史兼容标识。

## 2. 增加一层跨应用、可复用的 Capability

原有 `problem.*` 不是通用能力层，而是研究任务/应用情形，通常有“待估计未知量、可观测量、约束条件”。例如：

- `problem.ode-parameter-inference`：一般数学任务
- `problem.coronary-parameter-inference`：冠脉领域应用
- `problem.virtual-pci-counterfactual`：虚拟干预场景

**建议新增 `capability.*` 作为独立实体（正式迁移前不进入 data/）。** 它表达“必须解决的通用科学技术问题”，如可辨识性分析、正向求解、确定性优化、后验计算、数据同化或反事实预测。

当前提案为19项能力，分布为阶段Ⅰ6项、阶段Ⅱ8项、阶段Ⅲ5项。请注意：

- 主要归属阶段只用于导航；能力**可以被多个阶段调用**。例如灵敏度计算在正向建模中实现，却服务反演与控制。
- 一个问题可以需要多项能力，一个能力可以由不同家族、不同范式的方法提供。
- 方法→能力的关系表达**功能角色**，不能自动推断其论文证据或真实应用效果。
- `concern.*` 继续作为跨阶段的评价要求：物理一致性、可辨识性、模型/数值误差、可靠性、UQ、泛化等。一个概念可以既是独立研究能力（如“诊断可辨识性”），也对应横向质量关注点（“结果可辨识吗？”）；二者需在关系中区分。

## 3. “方法节点”应具有什么类型？

当前 `method.*` 的主语义类型**暂定**为以下11种，正式迁移前先作为独立审计标签：

| 暂定类型 | 主要语义 | 例子 |
|---|---|---|
| `problem_formulation` | 数学问题、目标或约束的表述 | Nonlinear Least Squares, Bayesian Inverse Problems |
| `method_family` | 一大类相关技术及其内部算法 | MCMC, SBI, Neural Operator |
| `algorithm` | 较明确的计算步骤或更新规则 | GN, LM, NUTS, EnKF |
| `numerical_scheme` | 数值离散、积分或近似规则 | FDM, FVM, FEM, RK |
| `model_family` | 一般模型/分布表示族 | GAN, Normalizing Flow, DDPM |
| `model_architecture` | 特定网络架构或结构变体 | DeepONet, FNO, PINO, Geo-FNO |
| `learning_strategy` | 训练损失、监督机制与策略 | Flow Matching, Physics-Informed Diffusion |
| `inference_strategy` | 推断工作流、条件化和代理应用 | Learned Forward Inversion, Generative Prior |
| `diagnostic_or_design` | 诊断信息量/参数可辨识或设计观测 | Profile Likelihood, Bayesian Experimental Design |
| `physical_model` | 物理机理模型/边界条件模型 | Windkessel, Structured Tree |
| `software_framework` | 实现基础设施与计算框架 | DiffTaichi |

这不是声称一个科学对象只具有一种性质。例如物理信息扩散也可以说是生成模型的某类变体。**`primary_kind` 只标注主要认知角色，允许附加 `facets` 及多重家族成员关系。**

不建议立即删除现有宽泛 `method.*`，或把它们迁移为 `family.*`：需要先确认学术含义、避免引入 ID 重定向错误，并继续保留原有论文和章节链接。

## 4. 边类型不能只用“谁是父节点”

对同一对方法，应先问“它们的关系是什么”，再决定其是否进入可视化的主 DAG。

| 关系层 | 现有/候选谓词 | 意义 | 是否等于历史创新 |
|---|---|---|---|
| 知识分类 | `member_of_family`, `subfamily_of`, `specializes` | 概念包含、特殊化、模型族成员 | **否** |
| 算法创新 | `extends`, `combines` | 有原论文支持的技术改变与融合 | **是，必须注明创新和瓶颈** |
| 技术借用（提案） | `uses_component`, `uses_training_strategy`, `adapts_algorithm_from` | 一个方法采用另一个方法的机制 | 不一定 |
| 理论/表述（提案） | `unifies_or_generalizes`, `equivalent_under_conditions` | 更一般的理论框架、特定条件下的等价 | 不一定 |
| 可用性与任务 | `supports_capability`, 既有 `addresses` 和 `uses_method` | 方法用于哪个研究能力/问题、承担什么作用 | **否** |
| 证据与教材 | `introduces`, `analyzes`, `applies`, `surveys`, `covers` | 学术证据与教材覆盖的贡献 | 可为创新提供依据 |
| 对比/先修 | `contrasts_with`, `depends_on` | 竞争关系、方法差异或学习依赖 | 否 |

**这些新谓词只是设计候选，尚未写入 JSON Schema 或 `data/relations/`。** 新关系应当在正式迁移时定义严格的 source/target 类型、方向、必需字段、证据强度、唯一性、无环规则（适用时）、双语说明和渲染方式。

特别要避免的错误：
- 把“X 可以用于反演”画成“X 是反问题方法 Y 的后继”；
- 把“模型 A 使用 B 的训练损失”直接等价于“A 融合了完整 B 架构”；
- 把“论文在某些数据集上有效”升级成“冠脉患者特异临床应用已验证”；
- 把“晚发表”当作“继承”的充分证据；
- 把“某个能力可由家族 F 提供”自动上升为“F 的每一个成员经文献验证可提供该能力”。

## 5. 三个探索视角如何共享数据

### A. 问题/能力视角

`研究阶段 → 可复用 Capability → 相关 Method/Family → 论文与专著`

例如：阶段Ⅱ → 后验推断 → MCMC、VI、SBI 等选择。它们未必具有**直接演化连接**，但都能为同一种计算能力提供不同方案。

### B. 方法体系视角

`Method/Family taxonomy DAG` + 方法类型 + 多重标签 + 跨家族关系。

允许相同方法从“神经算子”和“物理约束学习”两个入口被找到，但**底层只有一份方法实体**。

### C. 方法演进视角

`extends/combines` 及审核过的历史机制转移关系（若适合）构成局部的、带原始论文的 DAG。**允许多个不连通分量**，不应人为创建一根唯一祖先。

选择某个方法时，能够同时访问其概念归属、实际功能和真实谱系。视图是不同投影，不是分别维护的树或数据库。

## 6. 数据升级的兼容性原则

建议下一阶段先做**增量、可逆、兼容迁移**：

- 新增 `capability.*` 实体和验证规则时保留原 `problem.*`、`stage.*`、`method.*` ID。
- 在方法记录中增量增加审核后的 `primary_kind` / `facets`，但保留旧字段，或经配置兼容输出后再做 Schema 版本升级。
- 用审计侧表建立拟迁移关系，逐项核实学术论文后再写入权威 `data/relations/`。
- 为有争议的继承关系记录审计依据、证据定位、核查状态、原/新关系的完整迁移记录。
- 保留当前 Start Here / Landmark 的相对贡献语义和可选阅读规则。
- **不以新增边数或全图连通度作为质量 KPI**；更多关注问题→能力覆盖、边语义明确性、证据可靠性和方法导航成功率。

## 7. 推荐知识质量指标

建议后续报告下列指标，并区分“已经验证”和“仍需审查”：

1. **能力覆盖率：** 每种通用研究能力是否至少有一种有来源的求解策略。
2. **方法定位完整性：** 每个方法有主语义类型、家族归属、功能作用及代表文献。
3. **演进关系可信度：** 每条 `extends/combines` 都能解释具体改变和瓶颈，并直接定位原论文证据。
4. **典型问题链路完整度：** 从冠脉参数推断等问题能够追到观测、数值求解、反演、UQ、更新/干预所需技术。
5. **功能映射可到达性：** 点击每条“研究阶段/能力→方法”映射后，至少能定位节点或明确打开折叠区，而不出现“全图变暗但目标不可见”。

**下一步：** 先由结构审计结果决定真正应当新增或调整哪些能力、方法类型与关系定义；再按原论文核实高优先级关系。待学术结构稳定后再更新浏览器的可视化语义。
