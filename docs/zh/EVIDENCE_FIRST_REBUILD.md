## 一、重新确定项目目标与数据的权威性

Atlas 最终应回答三个层次的问题：

1. **学科知识体系：** 从可信论文和专著中抽象出哪些理论、问题表述、模型、方法家族、算法和训练/推断机制？它们怎样分类，哪些边界需要区分？
2. **真实方法演进：** 哪些工作提出、改进、扩展、融合或统一了哪些机制？依据原始研究的哪个部分？
3. **面向科研任务的导航：** 从 ODE/PDE 反问题、冠脉参数推断、快速正向模型、患者特异世界模型和虚拟 PCI 等问题出发，理解所需能力、候选方法及其适用条件和验证程度。

**数据建设的主方向：** 相关研究主题 → 候选论文/专著 → 质量准入 → 提炼技术主张与概念 → 分类及有证据的关系 → 研究任务映射 → 交互式知识视图。

可以用研究主题规划检索范围，但不能先固定方法树，再寻找论文凑齐它。方法数量、家族数量、边数量和图的连通性均**不是完成指标**。

### 旧数据与当前 UI 的定位

- `data/` 里的 61 方法、34 家族、58 篇论文、12 本专著、530 关系，属于**历史原型的初始研究样本**；它们不自动获得新政策下的正式学术准入。
- `audits/v09/` 的 11 种方法类型、19 项 Capability 及 10 条关系复核清单是**有用的假设/检查清单**，不是最终分类事实。
- `viewer-v08/`、`scripts/build_v08.py`、既有 CI/UI 测试，属于**可复用的界面与技术资产**。保留并允许逐渐改进，不因为重建学术内容而直接废弃。
- **不批量删除、不悄悄改变旧 ID。** 后续显式区分历史测试数据和正式通过审核的学术数据，再制定新旧映射与兼容迁移；最终网站不得把待审核原型误呈现为已经学术审定的图谱。

## 二、先用合格来源构建一个真实、可验证的小型知识切片

### 1. 检索范围由研究目标决定，不由旧节点清单决定

首轮从能够形成连贯技术讨论的主题出发：ODE/PDE 数值模型、确定性/贝叶斯反问题与可辨识性、优化与灵敏度/伴随方法、UQ/数据同化、Physics AI/神经算子，以及冠脉血流动力学中的参数推断与验证。

生成式建模、世界模型、模型预测控制/强化学习和虚拟 PCI 同样属于长期范围，但**是否在首轮产生独立方法节点，取决于筛选出的高质量来源及技术联系**，不是为了覆盖标签而强制添加。

需要兼顾传统经典与现代研究：不把近年的 ML 文献当成全部方法史，也不把旧经典强行接成现代技术的直接祖先。

### 2. 建立有审计记录的来源候选池

对每篇/本候选，首先确认正式版本、审稿状态、研究价值和重要局限，作出 **准入 / 待核查 / 不准入** 决定。旧的 58 篇和 12 本与新发现的来源均采用相同门槛。

每一小批完成之后形成**已通过清单及准入理由**；待核查来源不进入正式结论；明确不准入的低质量来源不用于填图。

可以先以大约 **15–25 篇论文及若干本核心专著**作为首个试验切片的工作量参考，**不是数量配额或最低目标**。优先可核实、内容有代表性、能形成真实概念联系的来源；若不合格宁可少收。

### 3. 从原文抽取知识，而不是直接复写摘要

对通过准入的来源，分别提炼：

- 研究对象、问题表述、假设、输入输出、数学/物理机制；
- 作者真正提出的创新、相对已有研究的区别、技术瓶颈、限制和验证证据；
- 文献中明确提到的先行研究、借用、推广、比较与独立贡献；
- 重要定义、定理、算法或实验的**可核对位置**（章节、公式、图表、页码等）；
- 对一本专著，优先抽取对应主题的章节与适用范围，不机械绑定整本书。

这些是**待组织的、带来源的知识主张**；不能仅凭文章同现的关键词直接生成演进边。

## 三、让知识本体从文献中归纳，再和已有设计对照

在第一批真实来源的技术内容充分整理后，决定哪些应成为独立概念节点：

- 研究问题/数学表述；
- 方法家族、理论框架；
- 具体算法、数值格式、模型架构、训练/推断策略；
- 物理模型与边界模型；
- 实现系统或软件（必要时单独标记）。

一个概念可以有多重分类关系，不要求所有概念处于相同抽象层级。**复用旧的 11 种主类型与 34 个家族提案作为检查材料，但允许拆分、合并、改名、增加或取消。**

方法间至少区分：

- **分类/包含：** A 是 B 的一种，或属于某家族；
- **真实演进：** 有证据表明一种方法扩展、改变或融合了另一方法，并能指出技术机制；
- **机制借用/统一：** 采用训练策略、推断步骤，或在特定条件下统一/推广；
- **功能及应用：** 方法可以服务于哪一类研究问题，受到什么假设、数据和证据范围限制。

不同关系不混成一根无语义箭头；历史先后与分类包含都不能自动算作创新。演进图可以天然不连通。

**Capability 层是否保留及如何划分，应在真实来源积累后决定。** 原三阶段研究主轴可以保留为用户探索的导航视角，但不强制所有方法必须适配预设的 19 种能力分类。

## 四、交互界面：从真实证据生成多个一致的知识视角

界面以**一套经过准入、可追溯的学术知识数据**生成视图，不维护另一套手工编造的图结构。原则上复用 v0.8 的全宽画布、缩放平移、搜索、全屏、小地图、路径聚焦、双语界面、详情抽屉与离线构建方式，并解决其可到达性问题。

### 三种相互关联的主要探索视角

| 视角 | 主要呈现 | 边界 |
| --- | --- | --- |
| **知识体系（Taxonomy）** | 概念类型、家族/子家族、重要方法、交叉归属；可折叠树/DAG 与检索 | 是学术分类，不把层级关系画成时间演进 |
| **方法演进（Lineage）** | 经原始研究审核的扩展、融合、机制借用、理论统一；按方法或主题聚焦 | 只画有具体证据与正确语义的关系；允许孤立节点与小组件 |
| **科研问题（Problem Pathway）** | 从问题→所需能力→候选方法→关键来源/验证证据的导航，尤其冠脉反演和数字孪生 | 能力映射与临床验证分开，不能把潜在迁移当成已验证疗效 |

**论文/专著不是图外附带的“参考文献列表”。** 在任何视角点选概念或连线，都能打开它的依据：原文出处、技术贡献、适用假设、争议、原文位置、书籍章节与相关来源。点击学术关系尤其需要展示“证据怎样支持这条边”。

### 交互的底线

- 关键词检索可直接定位所有正式来源支持的概念；没有演进边的概念也必须可达。
- 分类边、演进边、功能关系使用不同视觉编码，不能用漂亮连线暗示虚构的学术继承。
- 可切换整体/局部聚焦、前驱与后继、方法对照、证据详情；桌面和移动端都应可操作。
- 用户一眼能区分**正式来源支持**、**待审核线索**、**原型示例/历史记录**；默认正式知识视图不混入测试数据。
- 一篇论文可对应多个概念，一本专著可覆盖多个主题/章节；多入口访问不能产生重复的“权威实体”。
- 默认展示可读的局部结构；大图的拓扑与视图布局由真实学术关系决定，不要求人为制造总连通图。

## 五、重新组织后续开发阶段

原 v0.9-A 的只读结构审计**保持已完成**；原 B/C 的技术成果设想仍可复用，但顺序调整为“先真实来源、再本体定稿与证据关系”。下面阶段是**后续计划，而非已完成的工作**。

| 阶段 | 核心任务 | 可验收成果 |
| --- | --- | --- |
| **准备阶段：政策落地（本次）** | 确认并发布来源准入门槛，宣布旧目录为原型样本，重排路线 | 准入政策、路线图、README 状态说明；不改 `data/` 或 viewer |
| **v0.9-B（重定义）：首轮合格来源及归纳式本体** | 从研究主题检索，审核新旧论文/专著；从原文提炼首个真实知识切片；评估旧 11 类与 19 项 Capability；设计最小兼容 Schema 和正式/原型数据边界 | 准入来源清单、可核查的技术主张、概念与关系候选、本体/迁移方案，附审查记录 |
| **v0.9-C（重定义）：证据驱动的学术图谱** | 从已准入来源逐项确认方法、家族、历史演进、机制借用与功能映射；对旧数据进行复用/替换/撤出正式视图的可追溯迁移 | 一个已审查的端到端知识切片，重要关系有原始证据和定位；自动学术数据校验 |
| **v0.9-D：扩展与界面重构** | 扩展相邻高价值主题；实现知识体系/方法演进/科研问题三种共享数据的视角；继承并改进 v0.8 交互 | 可测试的证据驱动 UI，节点与关系均可查看原始来源；修复不可定位问题 |
| **v1.0：稳定发布** | 跨领域补充、术语一致性与学术质检、可视化验收、正式发布 | GitHub Pages/离线导出、可追溯的版本化学术数据、审查与维护流程 |

### 每阶段的验收优先级

1. **学术真实性：** 已确立的概念、重要关系及临床证据等级必须可追溯，而非仅仅满足 JSON Schema。
2. **概念清楚：** 区分问题、理论、方法、机制、物理模型、软件与临床验证，不因旧结构方便就保留概念错误。
3. **交互可达：** 能从研究问题或方法检索找到概念、来源和相关关系，不能点击后只剩灰色画布。
4. **工程可回滚：** 新旧 ID、迁移、审计记录与视图构建可复现；旧版原型保留，避免“切换新体系”时丢失历史。
5. **不使用虚假数量 KPI：** 不要求某个家族填满、每个方法配固定篇数或全部方法形成一棵树。

## 六、下一步的最小工作批次

**下一次实际建设不应马上大规模重构 UI，也不应机械从旧 61 个方法逐个找文献。**

优先完成一小批**文献筛选 + 原文归纳**：围绕“ODE/PDE 反问题的基本问题表述、求解与可信性，以及与 Physics AI/冠脉参数推断的连接”检索和审核经典及现代来源，同时纳入符合质量门槛的现有条目。逐篇记录能证明什么、不能证明什么，再从中提出第一批真实概念和关系。

这一批结束后，**用已核查的研究内容实测本体设计**，确认是否需要 Capability 层、是否要拆分某些旧 method 节点、演进关系需要哪些谓词；随后才进行正式 Schema 和前端重构。

我们将以小批次提交：每批有来源清单、准入理由、学术主张、拟变化的数据/界面、验证结果；**只有审核过的知识才进入正式图谱，未经审核的研究线索不伪装成正式结论**。
